- **X 统一订阅的周额度**：Grok、Cursor、Grok Bot 的包含额度是同一条每周额度池，三个卡片显示同一个每周剩余。第三方模型和超出包含额度的用量走预付余额，不再算进这条池子。
- **Cursor**：账号带 `isUnified` 时，改读 `get-sand-usage-status` 的 `usagePercent` 和周重置时间，套餐名用 `cursorPlanName`（Plus / Premium / Super / Ultra）。`usage-summary` 里过期的月度 Cursor Models / Other Models 不再当作当前额度；第三方模型也不会再显示成 Other Models 100%。未统一的 Cursor 月度计划保持原来的双池。
- **Grok**：周额度仍是 `creditUsagePercent`。`productUsage` 只是同一条池子的构成，不会再拆成额外额度条。有预付余额时在卡片上显示 Prepaid。统一订阅若只带回 `billingPeriodEnd`，仍按周额度解析。
- **Grok Bot**：同一条周额度。套餐名优先用 X 订阅档位，不再把 “Grok Bot Plan” 显示成套餐名。没有额度上限的按量花费不会画成一条百分比。
- 测试：全量 1,500 项测试 0 失败。覆盖统一周额度、过期月度摘要回退，以及未统一时仍走旧月度双池。

### 验证与边界

- 统一订阅的识别依赖 sand 接口上的 `isUnified` 或 `billingBrand`。该接口失败时，Cursor 仍回退到 `usage-summary`，旧月度计划不受影响。
- Grok 的产品用量百分比是共享池的构成，不是各自独立的剩余额度。
- 本机构建为 ad-hoc 签名、未公证；正式发布的签名、公证与安装包以 GitHub Release 流水线产物为准。

### English

- The X Subscription included usage is one weekly pool shared by Grok, Cursor, and Grok Bot. All three cards show that same weekly remaining. Third-party models and usage beyond the included pool come from prepaid balance, and are not part of the pool.
- Cursor accounts with `isUnified` now read `usagePercent` and the weekly reset from `get-sand-usage-status`, and show `cursorPlanName` (Plus / Premium / Super / Ultra). The stale monthly Cursor Models / Other Models split in `usage-summary` is no longer treated as current usage, and third-party models are no longer shown as Other Models at 100%. Legacy monthly Cursor plans keep both pools.
- Grok still uses `creditUsagePercent` for the weekly pool. `productUsage` is a breakdown of that same pool, not extra quota bars. A prepaid balance is shown as Prepaid. A unified payload that only includes `billingPeriodEnd` still parses as a weekly pool.
- Grok Bot uses the same weekly pool. The plan name prefers the X Subscription tier instead of the generic “Grok Bot Plan” label. On-demand spend without a limit is not drawn as a percent bar.
- Tests: all 1,500 tests pass. They cover the unified weekly pool, ignoring a stale monthly summary, and keeping the legacy monthly pools when the account is not unified.

### Verification and limits

- Unified detection depends on `isUnified` or `billingBrand` from the sand endpoint. If that call fails, Cursor falls back to `usage-summary`, and legacy monthly plans are unchanged.
- Grok product usage percents describe shares of the shared pool, not separate remaining allowances.
- The local build is ad-hoc signed and not notarized; official signing, notarization, and installers come from the GitHub Release pipeline.

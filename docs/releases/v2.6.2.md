- 安全修复：浏览器 Cookie 数据库查询的过滤条件（Cookie 名与域名片段）改为严格白名单，仅接受 DNS 主机名与标准 Cookie 名字符，堵住通过本地中转适配器或站点地址把 SQL 注入进浏览器 Cookie 库、进而读取任意站点登录态的通道。
- 安全修复：中转站请求中的绝对地址只允许发往你配置的中转域名（同协议）或内置官方探测域名（强制 https），第三方绝对地址一律回落到所配置的中转站点上，凭证与 Cookie 不会被导向未知服务器。
- 修复 2.6.1 引入的回归：官方服务（千问、Ollama、Codex/Claude 网页模式等）的 30 分钟浏览器 Cookie 轮换改为「请求成功后才写入钥匙串」。浏览器里是陈旧登录态时，不再覆盖仍然有效的已保存 Cookie；首次导入（无已存 Cookie）保持立即保存。
- 失效恢复更可靠：服务器拒绝已保存 Cookie 后的立即重试，改由「本次轮询是否刚读过浏览器」决定，不再依赖来源标签；轮换导入过的 Cookie 被拒时也能立即重试，恢复不再等最长 30 分钟。
- 浏览器读取退避期间如果仍有可用已存 Cookie，继续使用它，不再误报「缺少凭证」。
- 应用内更新加固：下载清单缺少 SHA-256 时直接拒绝（不再跳过校验）；解压后的 .app 会先通过 codesign 结构校验，运行中的 App 带有签名团队时还要求更新包来自同一团队；安装器启动失败会如实报错，不再静默退出。
- 凭证处理加固：移除钥匙串写入失败时把明文密码放进 `security` 命令行参数的回退路径（该内容对 `ps` 可见）。
- 文件权限统一：配置快照、官方账号槽位、第三方余额基线等本地文件改为 0600 私有权限写入，与账号 profile 的保护标准一致。
- 性能与能耗：第三方余额基线不再每个刷新周期无条件在主线程写盘（内容相同跳过、IO 移到后台队列）；Claude 网页分段缓存在 Cookie 轮换下增加条目上限。
- 配置恢复：所有来源都损坏/有损而回退默认配置时，有损原始数据的候选副本不再被随后的保存立即删除（损坏数据此前已有永久归档）。
- 工程化：CI 增加超时与并发取消、actions 固定到 commit SHA、仓库增加 `.swift-version`；打包脚本退出时清理临时目录与挂载的 DMG。

### English

- Security: browser cookie database queries now strictly whitelist the cookie-name and host filters (DNS host and standard cookie-name characters only), closing a SQL-injection path that a crafted local relay adapter or site address could use to read login cookies for unrelated sites.
- Security: absolute request paths in relay adapters may only target your configured relay host (same scheme) or the built-in vendor probes (https enforced); anything else falls back to the configured relay so credentials are never sent to unknown servers.
- Fixes the 2.6.1 regression: the 30-minute browser cookie rotation for official providers (Qwen, Ollama, Codex/Claude web, …) now persists only after a request built from the cookie succeeds, so a stale browser login can no longer destroy a working saved cookie. First imports (nothing saved yet) still persist immediately.
- Rejected saved cookies retry against the browser based on whether this poll already read the browser, not the cookie's source label, so rotated cookies also recover immediately.
- While browser-read backoff is active, a still-working saved cookie keeps being served instead of reporting a missing credential.
- In-app updates: a manifest without a SHA-256 is rejected outright; the extracted app must pass codesign verification (and match the running app's team when identity-signed); an installer that fails to start is reported instead of quitting the app silently.
- The `security` CLI fallback that exposed plaintext passwords in process arguments is removed.
- Local config snapshots, official account slots, and third-party balance baselines are now written with 0600 permissions, matching the profile stores.
- Third-party baselines no longer rewrite on the main thread every refresh cycle (skip identical writes, IO on a background queue); the Claude web segment cache is bounded under cookie rotation.
- When every config source is corrupt/lossy and defaults are restored, the lossy raw-data candidate is no longer deleted by the bootstrap save.
- Engineering: CI timeout and concurrency, actions pinned to commit SHAs, `.swift-version` added; the packaging script cleans up its temp directory and mounted DMG on exit.
- Full local suite passes (1,394 tests, including 9 new security regression tests); production sources build warning-free. The local package is ad-hoc signed and not notarized; published artifacts follow the GitHub Release workflow.

### English

- Credential storage hardening (the last P0 item): official account profile files no longer persist OAuth tokens. On launch, tokens are migrated losslessly into the Keychain vault under per-slot addresses (`official/codex|claude/profile/<slot>/oauth-json`). The migration cannot lose credentials: the vault write must succeed before the file is rewritten without tokens, failures keep the file intact for the next attempt, the process is idempotent and crash-safe. Account switching, import, and refresh flows are unchanged; files stay 0600 with metadata only. ⚠️ Downgrade note: after migration, downgrading to 2.6.4 or earlier means the old version cannot read tokens from the file — re-import the affected account once.
- OAuth refresh unification is complete: the Codex and Claude provider polling paths now run on the shared `OAuthRefreshPipeline` (refresh request, field merge, credential-file write-back, and vault write-back in one place; write-back failures are logged but never fail a successful refresh). Bonus fix: a new `account_id` from the token server is now honored (previously ignored).
- Code organization: the 1,033-line `AppConfigurationModel` is split into five focused files and the 1,200-line `RelayResponseInterpreter` into five (core + DeepSeek / Moonshot / Xiaomi MIMO / Sub2API vendor files), both verified as pure moves.
- Accessibility: about twenty classes of unlabeled interactive targets (icon-only buttons, custom switches/checkboxes, threshold steppers) gained bilingual accessibility labels and hover help; switches and checkboxes expose their selected state to VoiceOver; credential-edit and new-site dialogs gained Esc-cancel and Enter-default keyboard shortcuts.
- Full suite: 1,483 tests, 0 failures (23 new, covering vault slot addressing, migration idempotence and failure safety, provider refresh write-back assertions); the whole repo builds warning-free.
